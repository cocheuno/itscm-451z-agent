write, how to verify a submission in two minutes, the instance quirks that will bite, and the decisions
still open. Everything here was run in a clean environment against the current `main` before being
written down; the "measured" numbers are from that run.

## Module 3 (Sep 15 and 17): Rung 0 close-out, Rung 1 baseline

**Scaffolded.** `agent.analytics.features` (load, `text_of`, `time_split`), `train.py` (all plumbing, `--pipeline`
flag, compressed artifacts, model card), `predict.py` (versions, pin, cached load), harness rung 1 dispatch
and rung detection, the EDA notebook, the pagination acceptance test, `bakeoff.py`.

**Student writes.** `list_all` (exact code in lecture 02), three to five rules, the notebook answers,
`docs/sla.md` and `TARGETS_MIN`, ADR-0003, `build_pipeline("lr")`, the one-line harness edit that sets
`pred_priority`, model `category-v0.1` with card.

**Verify a submission.**

```
git checkout <branch> && pytest -q                       # lr pipeline test passes instead of skipping
python -m eval.harness --rung 1                          # classification 1.0, priority 1.0, routing 0.0 (expected red)
python scripts/bakeoff.py --rows rules,model:0.1         # rules ~0.15, model 1.0
ls -la src/agent/models/                                 # category-v0.1.joblib ~0.28 MB + .json with "adr": "ADR-0003"
```

**Quirks.** `git pull` on a clone that predates Sep 9 cannot work (unrelated history); the handout has the
re-clone. The harness exits 1 at Rung 1 because `routing_accuracy` is checked before A2 (decision below).
`pytest` count of 6 means the old clone.

**Measured.** Three default rules: 0.15 accuracy, 33 of 40 unclassified. TF-IDF+LR on August: 1.000; on
the 40 holdout: 1.0; fit 1.8 s; artifact 0.28 MB.

## Module 4 (Sep 22 and 24): build week, build review, v0.1

**Scaffolded.** `agent.analytics.llm_classify` (raw Messages API over `requests`, schema-enforced label set,
per-call cost from a price table, latency); `bakeoff.py` rows `rules`, `model:<v>`, `llm` (the LLM row only
appears when `ANTHROPIC_API_KEY` in `.env` is real); `CATEGORY_MODEL_VERSION` pin.

**Student writes.** ADR-0004 and `build_pipeline("gbm")`, model `category-v0.2`; a key in `.env`; the
`classify_incident` tool schema, governance row, ADR-0005; the audit entry in the poller; the bake-off run;
the memo in `docs/memos/`; ADR-0006 and the pin; the A1 PR; tag `v0.1`; the release with reports attached.

**Verify.**

```
python -c "from agent.analytics import predict; print(predict.versions(), predict.selected_version())"  # ['0.1','0.2'] <pinned>
python scripts/bakeoff.py --report /tmp/b.json && cat /tmp/b.json | head -30
ls src/agent/tools/schemas/classify_incident.json && grep classify_incident docs/governance/governance.md
git tag -l v0.1 && git show v0.1 --stat | head
```

**Quirks.** The GBM artifact is 2.7 MB compressed (SVD 50 components); at 100 components it is 4.7 MB and
trips the "few MB" rule, which is why the lecture says 50. The LLM row's cost depends on the model in
`.env` (`claude-sonnet-4-6` default, $3 and $15 per million tokens); the price table in `llm_classify.py`
also knows `claude-sonnet-5`, `claude-haiku-4-5` and `claude-opus-5`; any other model gives `cost_usd: None`
and the student must add a row. Structured output (`output_config.format`) is what makes the label set
enforced; if a model rejects it the API returns 400 with that field named.

**Measured.** TF-IDF+SVD50+HGB on August 0.994 / macro F1 0.990, fit 2.1 s; on the 40 holdout 1.0.

**Corpus caveat.** The synthetic text is separable by a bag of words, so every local model scores 1.0 and
the bake-off differentiates on latency and cost only. The lectures say so and make the student explain
it. Hardening the corpus (a share of tickets drawn from a cross-category generic phrase bank) would put the
baseline near 0.85 and make the 0.80 threshold bite; it costs a regenerated corpus, a new manifest and a
20-minute PDI reload. Still your call.

## Module 5 (Sep 29 and Oct 1): service requests, tool schemas, read-only tools, MCP

**Scaffolded.** `data/synthetic/kb.yaml` (22 published articles, one or two per subcategory, written to
match the clusters: VPN-GW-01 certificate, PRINT-SRV-02 spooler, ERP-APP-01 month end, IDP-01 MFA loop,
EDR-SIG-4471 false positive) and `cis.yaml` (five CIs with class, support group, IP; six groups).
`seed_pdi.py --groups --cis --kb` (groups and CIs idempotent by name; articles re-created each run;
`reset_pdi.py` removes KB and CI rows by their `[SYN]` title marker). `agent.tools.readonly`: keyword
versions of the three read tools plus `bind_all`. `agent.mcp_server`: an MCP 2.x server built from the
registry, read-tier schemas only, every call through `dispatch`. `scripts/mcp_client_check.py`: a stdio
client. `mcp>=2.2` in requirements (the 1.x `FastMCP` class was renamed `MCPServer` in 2.0).

**Student writes.** Raise a request in the catalog and read the three tables from Python; the audit
write in `Registry.dispatch` for the read tier (exact code in lecture 05a); the audit wiring in the MCP
server (05b); connect Claude Code or Claude Desktop to the server and report what the model did with the
tools.

**Verify.**

```
pytest tests/test_readonly_tools.py tests/test_tiers.py -q
python scripts/seed_pdi.py --dry-run --groups --cis --kb     # 6 groups, 5 cis, 22 kb
python scripts/mcp_client_check.py --call lookup_ci name=VPN-GW-01   # needs the student's .env and loaded PDI
grep -n "audit" src/agent/tools/registry.py                    # the student's entry
```

**Quirks, unverified live.** Three things could not be checked from here because there is no PDI
credential in the sandbox; each has a fallback in the lecture:

- `kb_knowledge` with `workflow_state=published`: the `itil` roles may not be allowed to publish; if the
  articles land as Draft, add `knowledge_admin` to `agent_svc`. The tools filter on `published`.
- `cmdb_ci` inserts with `sysparm_input_display_value=true` so `support_group` resolves by name; the
  group must exist first (`--groups` runs before `--cis` in the same invocation). Class names used are the
  out-of-the-box `cmdb_ci_server`, `cmdb_ci_netgear`, `cmdb_ci_appl`.
- Deleting CIs and KB rows via `reset_pdi.py` needs delete rights on those tables; if it 403s, delete
  the `[SYN]` rows in the UI once.

**Design notes.** The keyword matching in `search_kb` and `find_similar_incidents` is deliberately plain:
`LIKE` clauses on the instance, then a hit-count rank in Python. A2 replaces `keywords()` and the ranking
with sentence-transformer embeddings over the history CSV and `kb.yaml`, behind the same function
signatures, so nothing in the registry or the MCP server changes. `lookup_ci` returns sensitive fields on
purpose; the rule lives in the Module 12 output filter, and lecture 05b makes the student watch a real
client repeat an IP address so the rule has a face.

## Open decisions

1. **Harness gating by rung.** `check()` applies every threshold now; `routing_accuracy` is an A2 metric,
   so Rung 1 runs exit 1. Options: add a `gate_from` per metric in `thresholds.yaml` and have `check()`
   skip metrics whose rung has not arrived (needs an ADR, one small change), or accept the red exit until
   A2. The lectures currently say the latter.
2. **Corpus hardening.** See the Module 4 caveat.
3. **File locations the lectures prescribe.** `docs/sla.md`, `docs/memos/<date>-a1-model-selection.md`,
   ADR numbers 0003 to 0006. Change the lectures if you want different paths or numbers.
4. **Model in `.env.example`.** `claude-sonnet-4-6`. A current-generation model is a one-line change and
   the memo records whichever was used.
5. **`mcp>=2.2`.** The requirements comment said 1.1; the 1.x API is gone. If the student's laptop
   cannot install 2.x (Python below 3.10), the Thursday session needs a workaround.
